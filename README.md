# TokenHub

Пульт для Windows 11 над **Token Harbor** и **OpenCode**: хранит несколько API-ключей,
поднимает локальный OpenAI-совместимый прокси и переключает ключи, когда на одном
заканчивается бесплатный лимит. Диалог в OpenCode при этом не обрывается и
перезапускать его не нужно.

Интерфейс — WPF, стиль Fluent/Mica, тёмная и светлая темы, живёт в области
уведомлений (трей).

## Установка

1. Скачайте `TokenHub-Setup-<версия>.exe` на странице
   [Releases](../../releases/latest).
2. Запустите. Установка идёт в профиль пользователя
   (`%LOCALAPPDATA%\Programs\TokenHub`), права администратора **не нужны**,
   .NET Runtime ставить не надо — приложение самодостаточное.
3. Windows покажет предупреждение SmartScreen: установщик не подписан
   сертификатом code signing. «Подробнее» → «Выполнить в любом случае».
4. В конце установщик спросит, запускать ли TokenHub сразу, и включит автозапуск:
   при входе в Windows приложение будет тихо ждать в трее.

Требуется Windows 10/11 x64 и установленный [OpenCode](https://opencode.ai).

## Первый запуск

Сначала открывается короткий обзор программы — его можно пропустить. Затем, если
OpenCode ещё не настроен, приложение само открывает мастер: вставьте ключ Token
Harbor (`thk_...`), при желании включите установку скиллов и нажмите «Готово».
Мастер проверяет ключ запросом к `/v1/models`, сообщает, найден ли OpenCode, и
создаёт `opencode.json` с адресом локального пула. Ключ создаётся на
[tokenharbor.ai](https://tokenharbor.ai): регистрация бесплатная, карта не нужна,
и сам ключ показывается **один раз** — в карточке Universal Key, так что скопируйте
его сразу. Дальше:

1. Раздел **«Ключи»** → «Добавить» → вставьте ключ Token Harbor (`thk_...`).
   Ключей можно добавить сколько угодно.
2. Кнопка **«Применить в OpenCode»** прописывает в `opencode.json` адрес
   локального пула. В файле лежит служебный ключ пула (`thk_pool_...`), а не ваш
   настоящий ключ: настоящий подставляет прокси на каждом запросе.
3. Раздел **«Главная»** показывает состояние прокси, живую статистику пула и
   график запросов: токены за сессию и за сегодня.

Кнопка **«Настроить всё»** на «Главной» делает полную настройку одним нажатием:
создаёт файлы, ставит и запускает службу Windows (один запрос UAC) и подключает
OpenCode к пулу. Уже выполненные шаги она пропускает.

Мастер можно открыть заново кнопкой **«Настроить OpenCode»** там же, на
«Главной». Существующий конфиг он не ломает: перед изменением делается копия,
чужие провайдеры и `mcp` сохраняются.

Бесплатные модели Token Harbor (`*:free`) работают на любом ключе; платные модели
на ключе без нужного плана помечаются как недоступные именно для этого ключа и
**не** отправляют ключ в паузу. В «Настройках» можно выбрать модель по умолчанию
и включить режим «только бесплатные модели» — тогда прокси не пропустит платную
модель, даже если её попросит OpenCode.

## Как работает пул ключей

TokenHub поднимает локальный прокси на `http://127.0.0.1:8477/v1` (порты
8477–8486, если занято). OpenCode обращается к нему, а прокси подставляет ключ из
`settings.json`:

- ключи перебираются по порядку списка; активный запоминается;
- ответы `401` / `402` / `429` (`invalid_api_key`, `balance_zero`, `quota`,
  `credit`) — запрос повторяется **тем же телом** на следующем ключе;
- `invalid_api_key` помечает ключ недействительным, остальные ошибки — пауза
  `CooldownMinutes` (по умолчанию 30 минут);
- «плана нет на эту модель» не отправляет ключ в паузу, а запоминает
  недоступную модель;
- `region_blocked` не считается проблемой ключа — смена ключа тут не поможет;
- ответ, включая SSE-стриминг, отдаётся дальше построчно, поэтому диалог не рвётся.

Обученное состояние ключей (паузы, недействительность, недоступные модели)
переносится поверх файла настроек, так что постороннее сохранение не «разбудит»
ключ в паузе. Кнопка «Сбросить паузы и ошибки» снимает всё сразу.

### Служба Windows (необязательно)

Пока открыт TokenHub, прокси живёт внутри него — окно можно закрыть или свернуть
(«—» в правом верхнем углу), приложение уходит в трей и продолжает работать. Чтобы
пул работал вообще без TokenHub, в разделе «Ключи» есть
карточка «Своя служба»: она ставит службу `TokenHubPool`. Установка, запуск и
удаление службы требуют прав администратора — Windows один раз спросит (UAC).
Служба только читает `settings.json`, который пишет приложение, поэтому двух
писателей в один файл нет.

### Скиллы

Раздел **«Скиллы»** ставит готовые наборы инструкций для OpenCode. Коллекция
вшита в сам `TokenHub.exe`, поэтому ничего не скачивается. Скиллы сгруппированы
по назначению — разработка, тесты, дизайн, документы, Roblox, агенты, службы,
данные. Разделы свёрнуты, чтобы список не расплывался: нажмите на раздел, а затем
на название скилла — раскроются описание и кнопка «Скачать и установить». Есть
поиск (он сразу разворачивает найденное) и кнопка «Установить все»; папки
копируются в `%USERPROFILE%\.config\opencode\skills`. Установленные скиллы
отмечены и повторно не перезаписываются.

### Обновление

При старте TokenHub сам тихо проверяет последний релиз на GitHub. Если он новее,
на «Главной» появляется баннер «Доступна версия …» с кнопкой «Обновить» — или
«Позже». Кнопка **«Проверить обновление»** в блоке «Быстрые действия» делает то
же вручную.

## Где что лежит

| Что | Путь |
| --- | --- |
| Настройки и ключи | `%APPDATA%\TokenHub\settings.json` (+ `.bak`) |
| Дневная статистика токенов | `%APPDATA%\TokenHub\usage.json` |
| Счётчики по ключам | `%APPDATA%\TokenHub\stats.json` |
| Память ассистента | `%APPDATA%\TokenHub\memory.jsonl` |
| Журнал событий | `%APPDATA%\TokenHub\events.log` (ротация 512 КБ) |
| Резервные копии конфига | `%APPDATA%\TokenHub\` |
| Установленная служба | `C:\ProgramData\TokenHub\` |
| Конфиг OpenCode | `%USERPROFILE%\.config\opencode\opencode.json` |
| Скиллы OpenCode | `%USERPROFILE%\.config\opencode\skills\` |

Приложение меняет в `opencode.json` только `options.baseURL`, ключ провайдера и
`model`, и всегда делает копию файла перед изменением.

## Память ассистента

В TokenHub встроен MCP-сервер `tokenhub-memory` — тот же `TokenHub.exe`, запущенный
с флагом `--mcp-memory`. При старте приложение само прописывает его в `opencode.json`
(блок `mcp`) и добавляет короткую инструкцию в `instructions`, поэтому OpenCode
видит инструменты `memory_search`, `memory_save`, `memory_recent`, `memory_forget` и
`memory_stats` без ручной настройки.

- **Зачем.** Ассистент ищет в памяти факты о проекте вместо повторного чтения кода и
  сохраняет уроки после решения задач. Это экономит токены и не даёт дважды
  разбираться в одной и той же ошибке.
- **Где смотреть.** Раздел **«Память»**: список заметок, поиск, теги, добавление и
  удаление. Файл `memory.jsonl` — обычный текст, его можно редактировать вручную.
- **Приватность.** Всё лежит локально, без облака и без эмбеддингов. Приложение
  просит ассистента не сохранять ключи и содержимое `.env`, но заметки стоит
  просматривать перед публикацией диагностики.
- **Управление.** У каждой заметки есть `id`: `memory_forget` удаляет её, «Очистить»
  в приложении стирает всю память.
- **Профили проектов.** В настройках можно привязать папку к модели: «Применить»
  пишет `model` в `opencode.json` внутри проекта, не трогая остальные ключи.

## Про ключи и приватность

- В `settings.json` ключи хранятся зашифрованными (`enc:v1:...`) через DPAPI в
  области **машины** — служба работает как LocalSystem и должна читать те же
  ключи. Файл, скопированный на другой компьютер, не расшифруется: это защита,
  а не ошибка. Запись атомарная, предыдущая версия остаётся в `settings.json.bak`
  и подхватывается, если основной файл повреждён.
- `opencode.json` по-прежнему содержит ключ в открытом виде, потому что его
  читает сам OpenCode. При работе через пул там стоит служебный ключ пула
  (`thk_pool_...`), а реальный ключ подставляет прокси на каждом запросе.
- Прокси слушает только `127.0.0.1` и принимает запросы лишь с локальным `Host`,
  без чужого `Origin`, и только со служебным ключом пула или одним из ваших
  ключей. Страница в браузере или посторонняя программа не сможет тратить ваши
  токены.
- Диагностика (**«Настройки» → «Диагностика»**) собирает ZIP с журналом, версиями
  и `settings.json`, где ключи заменены маской.
- В этом репозитории **нет** адреса и секрета чужого регионального прокси:
  поля `ProxyBase` / `ProxySecret` при первом запуске — заглушки. Если у вас есть
  свой прокси, впишите его в разделе «Сеть и прокси».

## Сборка из исходников

Нужен .NET SDK 10.

```powershell
dotnet build   "TokenHub\TokenHub.csproj" -c Release
dotnet publish "TokenHub\TokenHub.csproj" -c Release -o "TokenHub\publish"
```

Служба собирается вместе с приложением в `TokenHub\publish\poolservice\`.

Один самодостаточный файл (без .NET на машине):

```powershell
dotnet publish "TokenHub\TokenHub.csproj" -c Release -p:PublishProfile=SingleFile
```

### Установщик

```powershell
powershell -ExecutionPolicy Bypass -File "installer\build-installer.ps1"
```

Результат — `installer\dist\TokenHub-Setup-<версия>.exe`. Сборка использует
`IExpress`, который уже есть в Windows: приложение и служба публикуются как
самодостаточные single-file сборки и упаковываются в один самораспаковывающийся
exe. Версия берётся из `TokenHub\TokenHub.csproj`.

### Тесты

```powershell
dotnet run --project "TokenHub.Tests\TokenHub.Tests.csproj" -c Release
```

49 проверок: классификация ошибок, cooldown, стратегии выбора ключа, сохранение
выученного состояния, DPAPI, подсчёт токенов (в том числе из SSE), дневной
счётчик, создание конфига OpenCode мастером и интеграционные проверки локального
прокси (Host/Origin, служебный ключ, режим «только бесплатные»). Код возврата
0 — всё прошло.

## Структура

```
TokenHub\              приложение (WPF, .NET 10)
  Assets\skills.zip   коллекция скиллов, вшитая в exe
  Services\            пул ключей, локальный прокси, настройки, пробы, автообновление
TokenHub.PoolService\  служба Windows, держит тот же прокси
TokenHub.Tests\        консольные тесты без NuGet-зависимостей
installer\             сборка установщика (IExpress) и его скрипты
.github\workflows\     сборка и публикация установщика по тегу
```
